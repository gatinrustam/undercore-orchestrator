# Панель оркестратора

Самостоятельный интерфейс оператора: серверы, технические назначения, незавершённые
операции и последние события с длительностью этапов. Не зависит от кабинета Undercore,
в режиме просмотра не опрашивает VPN-узлы и не меняет их состояние.
Управление включается отдельно параметром `--manage` и использует общий с CLI слой команд.

## Запуск

Оркестратор должен уже создать журнал актуальной версии. Запускайте панель от того же
сервисного пользователя с доступом к каталогу состояния. Создайте отдельный случайный
ключ; каталог для него должен быть закрыт от других пользователей. Пример для
стандартной установки (от пользователя, владеющего каталогом):

```sh
python3 - <<'PY'
import os
import secrets
path = '/etc/vpn-orchestrator/panel.token'
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL | os.O_NOFOLLOW, 0o600)
with os.fdopen(fd, 'w') as output:
    output.write(secrets.token_urlsafe(48) + '\n')
PY

undercore-orchestrator --settings /etc/vpn-orchestrator/settings.json panel \
  --token-file /etc/vpn-orchestrator/panel.token --port 8793
```

Команда создания не перезаписывает существующий ключ. Команда панели работает на
переднем плане; Ctrl+C останавливает только панель. Системный сервис автоматически
не устанавливается. Порт разрешён в диапазоне 1024–65535, адрес всегда `127.0.0.1`.

Откройте `http://127.0.0.1:8793/` и введите содержимое файла ключа. Для удалённого
сервера сначала установите SSH-туннель с одинаковым локальным и удалённым портом:

```sh
ssh -N -L 8793:127.0.0.1:8793 operator@your-server
```

`localhost`, произвольные Host и внешний reverse proxy не поддерживаются:
используйте именно `127.0.0.1` и настроенный порт. Не открывайте порт в интернет.
Ключ не передаётся в URL, аргументах запуска или localStorage. Не используйте
backend-токен: совпадение блокирует запуск. Старый `admin_token_file` игнорируется.

Сессия действует один час, хранится только в памяти панели и исчезает при её
перезапуске. «Выйти» отзывает текущую сессию. Для смены ключа замените его файл с
правами 0600 и перезапустите панель. Файл ключа панели не включён в стандартный
backup: после восстановления можно создать новый; VPN-идентичности от него не зависят.

## Что означают данные

- **Серверы:** регион, протокол, режим новых выдач, число назначений и лимит,
  последнее сохранённое состояние разрешения на управление узлом (lease).
- **Подключения:** технический ID, выбранный сервер, ревизия, завершённость выдачи
  или переключения, запрет доступа и результат последней операции.
- **События:** этап, действие, причина, длительность и request_id для сопоставления
  с журналами. Длительности вложенных этапов нельзя складывать.

Назначение сервера не означает, что пользователь сейчас подключён. Даже подтверждённое
разрешение узла не доказывает доступность интернета у клиента. Панель не заменяет
клиентскую проверку туннеля или внешний мониторинг.

Сводка SQLite согласована в пределах одного снимка; события читаются отдельно.
Таблицы серверов и назначений имеют страницы по 50 строк. Обновление выполняется
раз в 15 секунд, пока страница видима, и вручную кнопкой «Обновить». Если запрос
не удался, старые данные явно помечаются как устаревшие.

События поступают от обновлённых процессов API/worker через `events.jsonl` и
`events.previous.jsonl` в каталоге состояния: каждый не больше 256 КиБ, ответ содержит
не больше 100 последних событий. Файлы имеют права 0600. События могут теряться при
конкуренции или ошибке диска; это ограниченная диагностика, не аудит. До появления
первого события сводка базы работает независимо. Журнал событий не входит в backup
SQLite. В нём нет ключей, VPN-документов и произвольного текста ошибок агентов.

## Отдельный HTTP API

Этот API доступен только в процессе панели. Без `--manage` доступны только маршруты просмотра. Авторизация: сессионная cookie после
входа или `Authorization: Bearer <panel-key>` для чтения. Backend-ключ не подходит.
Проверка Host и источника запроса применяется и к API. CORS не включён.

| Метод и путь | Назначение |
|---|---|
| `POST /session` | Вход: JSON с единственным полем `token`; выдаёт cookie |
| `GET /admin/v1/overview` | Сводка; параметры `node_offset`, `connection_offset` от 0 до 1 000 000 |
| `POST /admin/v1/logout` | Отзыв текущей браузерной сессии |

POST требует точного заголовка `Origin: http://127.0.0.1:8793` (или выбранного порта).
Вход ограничен 20 попытками за минуту на процесс; тело — до 1024 байт.

Ответ обзора описан моделью `PanelOverview` в `orchestrator/domain/panel.py`:
`generated_at`, `nodes_total`, `connections_total`, `pending_creates`,
`pending_switches`, `denied`, оба offset, `page_size`, `nodes`, `connections`,
`events`, `events_available`. Ключи туннелей, конфигурации и адреса API узлов
не входят в проекцию ответа.

Ошибки: 401 — нет действующей авторизации; 403 — недопустимый Host/Origin;
413 — слишком большое тело входа; 422 — неверные параметры страницы;
429 — лимит входов (`Retry-After: 60`); 503 — журнал недоступен, повреждён или имеет
неподдерживаемую версию. Подробности внутренних исключений в ответ не передаются.
Без `--manage` изменяющие маршруты отсутствуют. Экспорт конфигураций панель не предоставляет.

## Управление

Для доверенного оператора запустите отдельный процесс с явным разрешением команд:

```sh
undercore-orchestrator --settings /etc/vpn-orchestrator/settings.json panel \
  --token-file /etc/vpn-orchestrator/panel.token --manage
```

Ключ этой панели теперь разрешает изменения. Backend-ключ по-прежнему не подходит.
Режим не меняется из браузера. Прежняя команда без `--manage` остаётся только для чтения.

Доступны добавление **уже установленного** Amnezia-агента, изменение режима и лимита
узла, отзыв доступа подключения, политики и журнал действий. Новый узел добавляется
в режим `draining`; оператор явно разрешает новые выдачи после проверки. Это не
установка VPN по SSH. Включение leases необратимо и требует их поддержки агентом.

`draining` прекращает новые назначения; `disabled` запрещает выдачу параметров,
но сами по себе эти режимы не удаляют peer. Для отзыва используется существующий
жизненный цикл `disable` с сохранением запрета и обработкой незавершённых переключений.
Ответ `disable_requested` не обещает мгновенный разрыв туннеля при недоступном узле.

### Контракт команд

| Метод | Путь | Результат |
|---|---|---|
| GET | `/admin/v1/capabilities` | `management`: включены ли команды |
| GET | `/admin/v1/policy` | Полная политика, её revision, `activation: restart_required` |
| GET | `/admin/v1/audit` | Последние 100 записей долговечного аудита |
| POST | `/admin/v1/commands` | Выполнение одной команды; тело до 16 КиБ |

Последние три маршрута существуют только с `--manage`. Авторизация и проверка
Origin такие же, как у остального API панели. Тело команды:

```json
{
  "operation_id": "operator-change-001",
  "action": "node.mode",
  "target": "node-nl-1",
  "data": {"expected_revision": 4, "mode": "draining", "capacity": 100}
}
```

`operation_id` и `target`: 1–80 символов `[A-Za-z0-9_-]`.
Оболочка проверяется моделью `domain/administration.py`; лишние поля запрещены.

| action | target | data |
|---|---|---|
| `node.save` | ID узла | NodeSettings без `api_key_file`, с `expected_revision` и необязательным `api_key`; для нового узла revision=0 и ключ обязателен |
| `node.mode` | ID узла | Текущая `expected_revision`, `mode`, `capacity` |
| `node.probe` | ID узла | Пустой объект; проверка идентичности агента |
| `node.restore` | ID узла | Пустой объект; восстановление управления по существующим правилам leases |
| `connection.disable` | connection_id | Пустой объект; операторский отзыв без изменения подписки |
| `policy.set` | `runtime` | `expected_revision` из GET policy и полный объект `policy` |

Идентичный повтор завершённой команды возвращает сохранённый результат. Другое
содержимое с тем же ID даёт 409 `operator_operation_conflict`. Незавершённая или
неудачная команда с тем же ID даёт 409 `operator_review_required`: сначала проверьте
состояние узла, затем при необходимости отправьте новую осознанную команду. Панель
не повторяет изменения автоматически. Таймаут не означает отсутствие изменения.

Устаревшая revision узла/настроек даёт `node_revision_conflict` или
`policy_revision_conflict`; некорректная политика — `invalid_policy` (422).
Внутренняя ошибка команды возвращает 503 `operator_review_required`, без текста
исключения или входного тела. Существующие ошибки жизненного цикла сохраняются.

### CLI и настройки

Та же команда выполняется из приватного JSON-файла (права 0600):

```sh
undercore-orchestrator operator execute --file /secure/change.json
undercore-orchestrator operator policy
undercore-orchestrator operator audit
```

Прежние `add/update/check/restore server` и `node save/probe/restore` также используют
этот слой и аудит. `connection ...` остаётся клиентом backend API с прежним контрактом;
для операторского отзыва с аудитом используйте `operator execute`.

Политики валидируются теми же моделями RuntimePolicy. Settings-файл должен иметь
права 0600, сервисный пользователь — право атомарной замены файла в его каталоге.
Другие поля settings.json сохраняются. Перед изменением сравнивается хеш полного
файла, после записи выполняются fsync и атомарная замена. Команды CLI/GUI сериализованы
общей блокировкой; ручное редактирование файла в это время не поддерживается.

Запущенные API/worker сохраняют прежние политики; новые процессы читают новые значения.
После изменения выполните контролируемый `undercore-orchestrator restart`. Панель
не перезапускает службы и не меняет политику внутри незавершённой операции.

### Журнал действий

`operator.sqlite3` (0600, отдельная схема 1) хранит ID операции, канал cli/panel,
тип команды, target, время, outcome и безопасный результат. Входные тела, ключи и
тексты исключений не сохраняются; для проверки повтора хранится только SHA256 команды.

До побочного действия синхронно фиксируется намерение. Недоступность аудита запрещает
операцию. `started` после аварии означает неизвестный результат; `failed` тоже не
доказывает отсутствие удалённого эффекта. Журнал не переигрывается автоматически и
не является защитой от администратора с правом изменения файлов. Общий ключ не даёт
персональной атрибуции. Автоматической очистки истории нет: контролируйте размер диска;
при его заполнении команды прекращаются. В API возвращается только 100 последних
записей, полная история сохраняется в резервных копиях.

Backup включает отдельный согласованный снимок аудита; он и снимок VPN-журнала не
образуют общую транзакцию. После восстановления по-прежнему обязательна сверка узлов.
