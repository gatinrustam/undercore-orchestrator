# Входящий API

API предназначен для доверенного backend, после проверки пользователя и права на
подключение. Все маршруты, включая health, требуют `Authorization: Bearer <token>`.
Значение берётся из отдельного файла на сервере. Внешний доступ — только через
HTTPS и ограничение источников; локально сервис слушает `127.0.0.1:8792`.
Все ответы имеют `Cache-Control: private, no-store`; тела и заголовки авторизации
не должны попадать в журналы reverse proxy и трассировки.

Машиночитаемые модели: [JSON Schema](../../contracts/orchestrator-connections.schema.json).
Версия URL `/internal/v2` и `schema_version: 1` — разные уровни версионирования.
`GET /internal/v2/capabilities` показывает реально включённые возможности.

## Операции

`{id}` — стабильный `connection_id`, возвращённый сервисом.

| Метод и путь | Назначение / тело |
|---|---|
| `GET /v1/health` | Состояние процесса и версия релиза; не проверка всех узлов |
| `GET /internal/v1/nodes` | Узлы, режимы, число назначений; не актуальный speed test |
| `POST /internal/v2/connections` | Создать или получить назначение: `DeviceRequest` |
| `GET /internal/v2/connections/{id}?device_id=…` | Состояние принадлежащего устройству подключения |
| `POST /internal/v2/connections/{id}/configuration` | Получить параметры: `ConfigurationRequest` |
| `POST /internal/v2/connections/{id}/renew` | Продлить: `device_id`, `expires_at`, `idempotency_key` |
| `POST /internal/v2/connections/{id}/disable` | Отозвать: `device_id` |
| `POST /internal/v2/connections/{id}/enable` | Включить ранее отключённое: `device_id`; срок доступа не продлевается |
| `POST /internal/v2/connections/{id}/recover` | Восстановить: `RecoveryRequest`, текущая `expected_revision` |
| `POST /internal/v2/connections/{id}/switch` | Операторское переключение: `SwitchRequest`; не открывать клиентам напрямую |
| `POST /internal/v2/connections/{id}/replace` | Совместимость замены: `device_id`, `expected_external_id`, `expires_at`, `idempotency_key`, необязательный `allow_create` |

Пример создания (синтетические значения):

```json
{
  "schema_version": 1,
  "device_id": "device-example-01",
  "name": "MacBook",
  "expires_at": "2027-01-01T00:00:00.000Z",
  "capabilities": [{"protocol": "amneziawg", "configuration_version": 1}]
}
```

Создание возвращает `Connection`: идентификаторы подключения, устройства и узла,
протокол, состояние и срок. Получение `/configuration` требует тех же
`schema_version`, `device_id`, `capabilities`, без имени и срока. Ответ дополнительно
содержит `revision` и `configuration` с `protocol`, `version`, `format`, `data`.
`data` содержит секретный документ для VPN-движка. Не логировать его и не помещать
в URL, аналитику, диагностический экспорт или открытый кэш.

## Повторы и восстановление

Повтор создания одного устройства с совместимым протоколом использует прежнее
назначение. Продление и переключение имеют ключ идемпотентности. При сетевом
таймауте повторять тот же запрос и ключ, не создавать новое устройство.

`recover` использует ревизию, которую получил клиент. Повтор старой ревизии не
переключает устройство обратно. Между новыми переключениями действует ограничение
1800 секунд. Изменение узла сохраняет `connection_id` и `device_id`.

Если отзыв старого доступа ещё не подтверждён, переключение не считается
завершённым. Фоновый обработчик продолжает незавершённые операции. Полная
недоступность прежнего узла может задержать переключение: это сохранённое
ограничение жизненного цикла, а не бесконтрольная выдача второго доступа.

## Ошибки

Тело прикладной ошибки: `{"detail":"machine_readable_code"}`. Примеры:

| HTTP | Смысл |
|---|---|
| 401 | Нет действительного служебного токена |
| 404 | Подключение не найдено/не принадлежит указанному устройству |
| 409 | Конфликт состояния, ревизии, идемпотентности или требуется обновление клиента |
| 410 | Доступ истёк/недоступен в запрошенной операции |
| 413 / 422 | Слишком большой или неверный запрос |
| 429 | Пауза между восстановлениями, `recovery_cooldown` |
| 503 | Нет подходящего узла, узел недоступен или идентичность не подтверждена |

Точный код зависит от операции. Нельзя трактовать любой 503 как доказательство
блокировки провайдером или повторять мутацию с новым ключом без проверки состояния.

## Совместимость v1

Сохранены `/v1/clients`, `/v1/clients/{id}` и операции
`configuration`, `amnezia`, `renew`, `replace`, `enable`, `disable` для существующего
backend. Новый код должен использовать контракт v2. Поле `mode: pilot` в старом
health сохранено ради совместимости и не определяет способ развёртывания.
