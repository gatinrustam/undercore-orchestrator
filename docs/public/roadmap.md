# Модернизация публичного проекта

Это план работ, не список реализованных возможностей.

## 1. Понятный публичный вход

README и навигация; честный список возможностей; инструкция для участника;
пример интеграции; статическая OpenAPI для v2 с проверкой актуальности в CI.
Лицензия MIT выбрана владельцем. Перед публикацией проверить канал приватного
сообщения об уязвимостях. Готовность: разработчик запускает пустой сервис и тесты
по документации без соседних репозиториев и настоящих серверов.

## 2. Самостоятельный VPN-узел

Выделить API/agent/runtime и их тесты в публичный UndercoreCo/vpn-node. Сначала
AmneziaWG 3.1; legacy WireGuard bridge не выдавать за полноценный новый драйвер.
Переносить исходники по allowlist, без серверных настроек и журналов; зафиксировать
происхождение стороннего кода и лицензии. Сохранить HTTP-контракт существующих
узлов, чтобы извлечение проекта не требовало одновременного обновления всей сети.

Критерий: установка и повторный запуск на чистой поддерживаемой Linux VM,
создание/экспорт/отзыв тестового peer, сохранение ключей после обновления.
На существующем сервере установка должна обнаруживать конфликт и останавливаться,
а не перезаписывать чужой VPN. Производственный сервер не служит тестом installer.

## 3. Установка узла из CLI

Предлагаемая команда provision server выполняет отдельную операцию установки по
SSH и регистрирует узел после успешной проверки. add server остаётся регистрацией
уже готового API. Runtime оркестратора продолжает использовать HTTPS. Команда
provision пока не реализована. SSH-ключи не становятся постоянным требованием API.

## 4. Развитие контрактов и драйверов

Выделить общий набор проверок драйверов, отделить lease transport от конкретного
агента, документировать переходы состояний и расширить объяснения кодов ошибок.
Не обещать динамические плагины до их реализации.

## 5. Точечный рефакторинг

Извлекать SQL из сценариев в небольшие операции хранения с сохранением общей
транзакции. Разделить длинные проверки узлов. Сборку конкретных драйверов оставить
в bootstrap. Отдельно планировать удаление legacy v1 и совместимых импортов.
Критерий: прежние проверки потери ответа, ревизий, leases и отзыва проходят без
ослабления; поведение клиента и работающих подключений не меняется.
